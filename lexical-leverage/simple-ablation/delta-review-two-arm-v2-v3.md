## New issues introduced by v3

- **[minor] C7's deterministic-slot shrink rule doesn't generalize to all six edge kinds.** The new C7 text applies one shrink mechanism ('halves its size ... keeping the edge's kind ... while shrinking its magnitude') uniformly to 'a deterministic edge slot (1-6)', but only some of those six kinds actually have a magnitude to shrink. The concrete numeric example given (200->100->50; 10**6->10**5->10**4) fits the oversized slot cleanly. It is unclear what 'halves its size' means for: the singleton/length-1 slot (already minimal -- nothing smaller to draw), the boundary value taken verbatim from the task's own test_case (halving it detaches the probe from the actual documented boundary it's meant to test), and arguably the negative/below-range slot (shrinking magnitude could move a below-range value back into range, changing what the slot is testing). *Fix:* Scope the halving rule explicitly to the slot kinds it actually fits (oversized; whitespace-only/all-equal, by shortening length), and give the other kinds (singleton, boundary-from-test_case, negative/below-range) either an explicit 'no adjustment, timeout is logged and the task is flagged' fallback or their own kind-appropriate replacement rule.
- **[minor] INCONCLUSIVE-DUE-TO-ORDER-CONFOUND's relationship to the Diagnosis section is unstated.** Consuming decision says 'INCONCLUSIVE -> apply the diagnosis below' (the floor/ceiling/mid-range/memorization routing). The new INCONCLUSIVE-DUE-TO-ORDER-CONFOUND label is produced upstream, during the primary-analysis sensitivity check, not by that diagnosis branch -- but the document never says whether this label is terminal (reported as-is, diagnosis skipped) or should still be routed through the floor/ceiling diagnosis. The same ambiguity already existed for INCONCLUSIVE-DUE-TO-EXTRACTION-NOISE in v2 and was not flagged by either review, so this is not a v3 regression, but the new branch inherits an unresolved gap rather than closing it. *Fix:* State once, generically, that any of the named INCONCLUSIVE-DUE-TO-* labels (ORDER-CONFOUND, EXTRACTION-NOISE, MEMORIZATION) are terminal and reported as-is, bypassing the floor/ceiling diagnosis, which applies only to plain INCONCLUSIVE.
- **[minor] v3's own change-summary undercounts the delta review's findings.** The preamble states 'v3 applies a delta review of v2 (one new main finding, three minor)' but does not mention that a partially-resolved item carried over from the v1->v2 review (C7's deterministic-slot coverage) was also addressed in this revision. Purely a documentation/self-description gap in the preamble text, not a design flaw -- the fix itself is present in the document. *Fix:* Update the preamble to '... (one new main finding, one new minor finding, two consistency notes, and one carried-over partially-resolved item)' or similar, so the stated count matches what the record actually changed.
