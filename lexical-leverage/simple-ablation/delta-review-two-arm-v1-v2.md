## New issues introduced by v2

- **[main] No consuming-decision rule for the two recomputed primary-analysis numbers (all-30-tasks vs. excluding-the-5-C6-tasks).** The revised Call order section (added to fix D's main finding 1) commits to reporting the primary analysis twice — once over all 30 tasks and once with the 5 C6 tasks excluded, because those 5 tasks have a temporal A/B ordering asymmetry the other 25 don't. But neither the Call order paragraph nor the Primary analysis / Consuming decision sections say which number governs the SUPPORTED/FALSIFIED/INCONCLUSIVE call, or what happens if the two disagree (e.g. one crosses the decision boundary and the other doesn't). This is exactly the kind of undisclosed, decided-after-the-data-are-in analytic flexibility that D's original main finding 1 was about — v2 fixed the internal contradiction but left the new branch's decision rule unspecified. The extraction-failure analog (secondary analysis 2) has exactly this kind of named disagreement-handling rule (INCONCLUSIVE-DUE-TO-EXTRACTION-NOISE with a magnitude threshold); this new branch has none. *Fix:* Either designate one of the two numbers (most naturally the all-30-task one, since it's the pre-specified primary contrast) as decision-governing and make the excluded-5-task number descriptive only, or add a named branch (e.g. INCONCLUSIVE-DUE-TO-C6-ORDER-CONFOUND) with a pre-specified magnitude/classification-flip threshold analogous to the extraction-noise rule.
- **[minor] New control C8's stated slot-comparison count (150) is inconsistent with the described procedure.** C8 says: 'for the five C2 tasks, compare which slots raise under the canonical solution against which slots raise under each of the two hand-written C2 implementations. Report the slot-level agreement rate (150 slot comparisons).' Taken literally — 5 tasks × 20 slots/task × 2 implementations to compare against — gives 200 comparisons, not 150. Verified arithmetically (5×20×2=200); no reading of the stated procedure reproduces 150. This is a new control introduced in v2 (a response to D's main finding 3), so C/D never had the chance to flag it. *Fix:* Recompute and correct the stated count (should read 200 under the literal procedure), or, if some subset of slots is meant to be excluded from the comparison (e.g. the test_case-derived boundary slot), state which slots and why so the arithmetic is checkable.
